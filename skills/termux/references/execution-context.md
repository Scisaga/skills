# 执行位置与现有通道

连接方式和执行环境是两件事。USB/ADB 可以用于查看已运行的 Xfce、打开其中的终端并输入命令；不要求先建立 SSH，也不要求先打开 Termux Activity。

## 按问题选择位置

| 当前任务 | 优先操作位置 | 必要现场信息 |
|---|---|---|
| Xfce 主菜单、桌面图标、Thunar、窗口主题、guest 字体/应用配置 | 当前 Xfce 界面；需要命令时在该桌面的终端执行 | 实际菜单/窗口、guest HOME、当前 DISPLAY 与桌面会话 |
| Android 分辨率策略、应用权限、输入法、系统电源设置 | 已有 ADB shell 或 Android 正式设置界面 | 当前连接设备和对应系统设置 |
| 原生 Termux 的 runit、Boot、包、API、native 应用包装器 | 原生 Termux 环境，沿当前已授权通道进入 | native HOME/PREFIX、实际服务或进程 |
| 用户要求部署或排查 SSH、验证脱离 USB 的连接 | 对应的 SSH/ADB 工具，按该任务检查身份和网络 | 明确的目标地址、已核对的主机身份与连接结果 |

已有 Xfce 能操作菜单和终端时，不要先试 `run-as com.termux`、切到 Termux Activity、重启桌面或探测 LAN SSH。ADB shell 无权读取 Termux 私有目录，不表示当前 Xfce 终端也无权访问自己的菜单和设置；在正确环境中验证实际限制后再决定是否需要跨环境步骤。

## 小范围问题的最短流程

1. 直接查看用户指出的界面。例如重复菜单先打开 Applications 菜单，确认数量、标签及位置，不先做整机诊断。
2. 在当前 Xfce 启动终端，只读取相关菜单文件、用户覆盖项和配置。先确认当前 HOME、DISPLAY、XDG_CURRENT_DESKTOP；不要套用上一台设备的用户名、目录、坐标或连接文件。
3. 备份并修改最小范围，保持会话、现有窗口和未保存工作。临时脚本通过已有 USB 传输，在 Xfce 终端执行；结果取回后删除本次精确临时文件并关闭自己创建的终端。不得因此新增常驻命令服务。
4. 回到原界面核对真实结果。文件存在、命令退出成功或异环境的可见性查询不能替代实际菜单验证。Gio/Garcon 的结果需要当前 XFCE 环境；缺少 XDG_CURRENT_DESKTOP 的 PRoot 诊断 shell 可能把 OnlyShowIn=XFCE 的项目误判为不可见。

只问“是否应该改成单击”时，先回答取舍；用户要求实际调整后再操作。明确要求“看看菜单”“调整重复项”时，要完成现场检查和修改，不反复询问是否继续。用户纠正执行位置或通道时立即执行纠正，不用旧流程为原先错误的选择辩护。

## 连接与验收范围

- USB 成功连接就是 USB 通道的事实。未使用 SSH 不影响 USB/Xfce 任务完成；不把额外 SSH 的未知密钥、未监听或超时报成 USB 失败或当前任务阻碍。
- 当前任务可以在已有通道完成时，不测试另一通道。历史设备配置仅供参考，不能直接作为当前目标；设备切换后只核对本次实际连接对象，不尝试旧地址。
- SSH 确属任务所需时继续严格校验主机身份；不得为了省事关闭校验。某个部署脚本要求 SSH，是该脚本的适用条件，不是所有 Termux/Xfce 工作的前提。
- 清理本任务创建的转发、脚本和诊断进程。ADB 若原已被用户使用，不擅自关闭其其他会话；停止自己启动且不再需要的服务。只有用户任务要求“不依赖 ADB 的 SSH 交付”时才断开 ADB 后验证 LAN SSH。
