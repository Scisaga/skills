# 二阶段比对与过滤优化

## 核心原则

不要只用“最后一条字幕离视频结尾多少秒”判断字幕是否可用。末条时间码差能发现明显错配，但长片尾、无片尾字幕、流媒体版本差异和影院/蓝光片尾差异都会造成 3 到 10 分钟的大间隔。

## 阶梯式校验

1. **基础有效性**：文件可解码、可解析时间码、含中文、字幕条数足够。
2. **身份匹配**：标题、年份、季集号、完整文件名、平台、版本 token、字幕组、官方/精校标签。
3. **结构校验**：首条字幕不能离开头过远；字幕跨度不能明显短于主体内容；时间码应覆盖主要剧情段，不只集中在开头。
4. **内嵌原文锚点**：若视频带英文或其他非中文文本字幕流，先抽取该流，使用 cue 中点最近邻比对中文字幕时间轴。匹配比例高、偏移中位数和 90 分位误差低时，可比单纯片尾时长差更可信。
5. **时长校验**：差值在阈值内直接通过；差值 180 到 600 秒进入二阶段比对；超过 600 秒默认拒绝但保留强匹配例外。
6. **抽样比对**：在 10%、25%、50%、75%、90% 剧情位置抽取附近字幕，结合视频截图、音频语音区间或人工快速查看确认。
7. **报告落点**：自动确认不了的强候选不能消失，应落到 `needs_compare` 或 `manual_check`。

## 状态分类

- `completed`：基础校验和时长/结构校验均通过。
- `manual_check`：字幕已落盘，但存在大间隔或证据不完整，需要人工抽查。
- `needs_compare`：候选已下载，基础校验通过，但不能只凭末条时间码决定。
- `retry_download`：候选存在，但 API、签名、浏览器校验或网络失败。
- `retry_extract`：下载包存在或页面明确有字幕，但解压没有得到有效字幕。
- `review_relaxed_filter`：被机器翻译、低评分或语言标签过滤，但没有更好候选。
- `hard_reject`：标题、年份、季集、语言或字幕内容明显错误。

## 大时长差处理

对 `duration_mismatch diff <= 600s` 或“最后时间码差 <= 600s”：

- 如果内嵌非中文字幕时间轴锚点强匹配，允许自动通过，并在报告原因中写出 coverage、median offset、p90 offset。
- 内嵌原文时间轴首次抽取可能较慢；脚本会把结果缓存到 skill 的 `.cache/reference-cues/`，后续同一视频大小和修改时间不变时直接复用。
- 如果标题/年份/版本强匹配，标记 `needs_compare`。
- 如果官方字幕、可信字幕组或页面片源时长匹配，标记 `manual_check` 或 `needs_compare`。
- 如果只是标题弱匹配，保留候选但不落盘。

对 `diff > 600s`：

- 剧集、纪录片短片、明显错片直接 `hard_reject`。
- 电影若完整文件名、页面时长和抽样比对都强匹配，可人工确认后保留。

## 未完成项重试

未完成报告里出现以下内容时，不视为最终失败：

- `api_failed`
- `api_non_json_or_error`
- `signature`
- `下载失败`
- `no_sub_files`
- `extract_or_no_subtitle_files`
- `Windows 7-Zip 未能解出有效文件`
- `found no acceptable non-machine Chinese candidate`

处理方式：

1. 保留候选 URL 和下载 URL。
2. 使用 `.env` 代理重试。
3. 对 SubHD 浏览器校验失败的候选，进入浏览器辅助下载队列。
4. 对“机器翻译”过滤导致无候选的项目，降低优先级但保留人工确认入口。
5. 对已下载但大间隔的候选，优先抽样比对，不要反复重新搜索。
