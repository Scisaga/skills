# 原创技术信息图视觉预设

## 定位

`technical-infographic` 用于把系统架构、工程流程、方案比较、分类关系和故障链路转成一眼可读的技术解释图。它吸收现代技术教育信息图常见的结构化表达，包括高对比标题、浅色分区、描边图标和明确连接线，但不复刻任何创作者的品牌或具体作品。

第三方帖子只用于观察视觉规律。不得下载到项目资产、描摹原图、复制 Logo、复用原始图标、照搬文案或重建具有识别度的完整版式。输出中不要出现 `ByteByteGo-inspired` 等来源声明，除非用户明确要求在研究说明中引用来源。

## 启用方式

初始化时指定：

```bash
bash skills/build-narrated-presentation/scripts/run.sh init \
  --output /path/to/project \
  --name "项目名称" \
  --deliverable static_pptx \
  --input-document /path/to/source.md \
  --input-review /path/to/input-review.json \
  --visual-style technical-infographic \
  --visual-theme light
```

项目已有时，修改 `project.json.visual` 后重新生成视觉链路：

```json
{
  "visual": {
    "style_preset": "technical-infographic",
    "theme": "light",
    "density": "presentation"
  }
}
```

不要在只改音频模式中切换风格或主题。

## 设计标记

### 画布与网格

- 使用 `1600×900`，四周安全边距不少于 `64px`。
- 标题区占顶部约 `150–190px`，主图占余下空间。
- 主图使用清晰的列、泳道或卡片网格；卡片之间至少留 `28px`。
- 每页只保留一个核心判断、一个主要阅读方向和最多五个主要模块。
- 卡片圆角使用 `18–28px`；描边使用 `2–4px`，同页保持一致。

### 字体层级

- 标题：`48–64px`，粗体，尽量不超过两行。
- 副标题：`20–26px`，用于解释本页判断，不堆背景材料。
- 区块标题：`26–32px`，粗体。
- 卡片标题：`22–26px`，粗体。
- 正文与连线标签：`18–22px`，视频画面中不得更小。
- 标签优先使用 1–6 个词；完整解释放入旁白，不塞进卡片。

字体优先使用项目指定的无衬线字体；没有品牌字体时使用跨平台可替换的无衬线字体族。不要依赖只有制作机安装的特殊字体。

### 亮色主题

| 用途 | 建议颜色 |
|---|---|
| 背景 | `#F8FAFC` 或 `#FFFDF7` |
| 主文字与描边 | `#151922` |
| 蓝色系统模块 | `#DDEBFF` / `#2F6BFF` |
| 紫色智能模块 | `#EDE4FF` / `#7C4DFF` |
| 绿色成功模块 | `#DDF7E8` / `#22A06B` |
| 橙色提示模块 | `#FFF0D6` / `#F59E0B` |
| 红色异常模块 | `#FFE0E5` / `#E5484D` |

大面积使用浅色填充，饱和色只用于标题条、编号、箭头和关键状态。不要让每张卡片同时出现多个强调色。

### 暗色主题

- 背景使用 `#111318`，卡片使用 `#1B1F27` 或 `#222733`。
- 正文使用 `#F5F7FA`，次要说明使用 `#AEB7C6`。
- 使用紫、青、黄或粉作为分区色；同页最多保留三种强调色。
- 暗色卡片仍需可见边界；使用浅灰描边或颜色标题条，不依赖阴影区分。

## 版式家族

根据页面语义选择一种 `layout_family`，不要在同一页混用多套阅读语法：

| 家族 | 适用内容 | 结构 |
|---|---|---|
| `flow` | 请求链、生产链、故障链 | 单向流程，异常或反馈使用独立支路 |
| `comparison` | 方案、角色、协议比较 | 对称的二至四列，维度纵向对齐 |
| `matrix` | 能力、阶段、权限、覆盖关系 | 有明确行列标题的网格 |
| `taxonomy` | 类型、组件、领域地图 | 中心概念加三至五个分支 |
| `timeline` | 演进、分阶段交付 | 单向时间轴加少量里程碑 |

复杂架构优先拆页：

1. 第一页给出全局骨架；
2. 后续每页放大一个关键分支；
3. 最后一页回到结论、边界或选择建议。

不要为了复刻社交平台单图而把全部细节压进一页。

## 图标与连接线

- 使用原创的扁平描边图标，统一 `3–5px` 深色描边和圆角端点。
- 一个图标只表达一个对象，例如用户、文档、数据库、服务、模型、告警。
- 图标使用两至三种填充色；同类对象必须复用同一图形语法。
- 默认流程使用深色虚线正交箭头；成功路径可用绿色，异常和回退使用红色。
- 箭头必须真正接触源对象和目标对象，避免穿过文字、卡片或其他连接线。
- 在线上方放短动词，如“校验”“路由”“写入”“回退”，不要写完整句子。

## SVG 分组

让原始 SVG 即使不播放动画也完整可读，并使用稳定分组：

```xml
<g id="base">...</g>
<g id="title">...</g>
<g id="beat_01">...</g>
<g id="beat_02">...</g>
<g id="beat_03">...</g>
```

- `base`：背景、固定网格和页脚；
- `title`：栏目、标题和副标题；
- 每个 `beat_*`：一个完整语义模块及与它强关联的连线；
- 不要把一个图标的边框、填充和文字拆到不同动画组；
- 连接多个模块的箭头通常与目标模块一起出现。

## 动画适配

现代技术信息图中的 GIF 常用循环脉冲、发光点或加载器，但旁白演示只取其“快速建立阅读关系”的原则：

- 标题在 `0ms` 淡入；
- 第一个模块在 `120ms` 出现；
- 后续模块按阅读方向每隔约 `130ms` 出现；
- 流程使用方向性 wipe，比较卡片使用 fade；
- 在 `1000ms` 内完成结构建立，之后保持稳定；
- 不制作无休止循环、逐字跟读或需要观看动画才能理解的关系。

## 交付前检查

- 不看旁白能否在五秒内找到标题、阅读方向和核心结论；
- 是否只有一个主要版式家族和一个核心判断；
- 正文字号是否至少 `18px`，卡片是否能从视频缩略图中区分；
- 颜色是否表达稳定语义，而不是随机装饰；
- 所有箭头是否有明确起点、终点和方向；
- 是否存在第三方 Logo、原始图标、原文或过度相似版式；
- 动画结束后，静态画面是否仍然完整；
- 密集内容是否应该拆成多页。
