# 未来路线、技术愿景与商业蓝图叙事

## 适用范围

制作未来路线、技术愿景、目标能力、生态布局或商业蓝图页面时，使用本规范统一标题、标签、正文、图示和旁白的表达。它适用于获授权的新写内容和 `adapted` 逐页稿；`identity` 绑定的逐页稿必须保持原文，只能先提出修改建议，得到用户授权后再切换为 `adapted`。

## 主叙事顺序

页面主体按以下优先级建立叙事：

1. **方向**：明确要走向哪里，以及下一阶段推进什么；
2. **价值**：说明给客户、业务、组织或生态带来的结果；
3. **规模化逻辑**：交代能力如何从单点验证走向复用、复制、平台化或网络效应；
4. **明确主张**：用一句可复述的判断收束页面，不用免责声明代替结论。

标题应表达目标状态或战略方向；标签应标示阶段、能力、角色或增长杠杆；正文负责说明价值与规模化链路；旁白补足因果关系、推进顺序和取舍，不重复朗读脚注，也不连续复述同一组防御性限定。

不要在标题、标签、正文和旁白中反复堆叠“建议”“仍在规划”“尚未跑通”“不代表已有能力”等措辞。存在重要不确定性时，保留一次准确、可定位的边界说明即可；不能用含糊乐观措辞掩盖会改变决策的风险。

## 事实边界的放置

主体与边界分层表达：

- 主体呈现愿景、价值、推进逻辑和目标状态；
- 页脚或来源说明标注当前基础、假设、依赖、数据口径和目标时间；
- 验收记录或内部 QA 保存更完整的证据差异、未决事项和实现状态；
- 法律、安全、财务或重大事实误导风险必须在受众作出判断前清楚可见，不能为了视觉简洁移入不可见区域。

低干扰不等于隐藏。边界说明要让受众能够区分“当前已经具备”“正在推进”和“目标形成”，但不应在页面主体多处重复抢占注意力。

## 时态与措辞

用时态明确状态，不靠连续免责声明自证谨慎：

| 状态 | 推荐表达 | 禁止混淆 |
|---|---|---|
| 当前事实 | “已完成验证”“当前覆盖”“现有基础是” | 没有证据时写成已实现 |
| 进行中 | “正在推进”“下一阶段打通”“逐步扩展” | 把进行中写成稳定能力 |
| 目标态 | “将形成”“面向规模化”“推进成为”“目标覆盖” | 用现在时包装规划能力 |

例如，主体可写“面向规模化交付，形成可复制的行业解决方案”，脚注再说明“目标态；当前已完成 A 场景验证，B/C 场景待验收”。不要把标题写成“建议探索行业复制（尚未跑通，不代表已有能力）”，也不能在只有规划时写“已形成规模化行业平台”。

## 验收标准

未来路线与商业蓝图页必须同时满足：

- **愿景先行**：五秒内能识别方向、目标状态或战略价值；
- **主张清晰**：页面给出可复述的判断，并说明至少一条价值或规模化逻辑；
- **边界克制**：必要限定集中、准确且低干扰，主体没有无风险依据的防御性措辞堆叠；
- **事实不失真**：当前、进行中和目标态可区分，规划能力没有被包装成既成事实，重大风险没有被隐藏。

这是一项人工语义验收。将结论记录在 content、visual 或 narration 审批摘要及内部 QA 中；不要声称结构脚本能够自动证明愿景力度或事实真实性。
